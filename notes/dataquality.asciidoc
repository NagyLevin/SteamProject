
= Data Quality Assessment

== Missing Values

I created the `get_missing_values()` function to examine
the number and percentage of missing values in each column.

The function uses `df.isna().sum()` to count missing values
and `df.isna().mean() * 100` to calculate their percentages.

=== Results

All five columns contain 0 missing values (0.0%).

=== Interpretation

No missing values were detected in the original dataset.
Therefore, no missing value imputation or row removal
is required at this stage.

However, the absence of missing cells does not guarantee
that every purchase record has a corresponding play record.
This relationship will be examined separately.

== Duplicate Records

I created the `get_duplicates()` function to
identify fully duplicated rows in the original dataset.

The function uses `df.duplicated().sum()` to count
records that are identical to previously occurring rows.

It also calculates the percentage of duplicate
records relative to the total dataset size.

The purpose of this analysis is to identify possible
redundant records that could affect the accuracy later.

The dataset contains 707 fully duplicated rows out of
200,000 total records, representing approximately 0.35%
of the dataset.

The duplicated rows will first be examined to determine their behavior types and whether they represent redundant information.

To investigate the duplicates further, I created the
`inspect_duplicate_records()` function, which uses
`value_counts()` to examine their distribution
across behavior types.

All 707 fully duplicated records belong to the
`purchase` category. No fully duplicated `play`
records were detected.

Further inspection showed that some purchase
records appear multiple times for the same user
and game.

Examples include games from the Grand Theft Auto
series and Sid Meier's Civilization IV.

One possible explanation is that the duplicates
were introduced during the original data collection
or processing procedure. However, the exact cause is unknown for me.

I used `duplicated(subset=["user_id", "game_name"],
keep=False)` to identify multiple play records
associated with the same user and game.

The analysis identified 24 matching play records.

Unlike the previously identified 707 fully duplicated
purchase records, these play records contain different
playtime values.

For example, one user has two recorded playtime
values of 135.0 and 2.0 hours for
Sid Meier's Civilization IV.

Summing the values could potentially overestimate
total playtime if the measurements overlap.

I will keep the bigger number for each user.

== Invalid, Negative and Zero Values

I created the `value_check()` function
to identify potentially invalid numerical values
in the original dataset.

Since the `value` column has different meanings
depending on the behavior type, purchase and play
records were examined separately.

For purchase records, I checked whether all values
were equal to 1.0 using the `!=` operator.

For play records, I used comparison operators to
identify negative and zero playtime values.

I also used `np.isfinite()` to identify missing
or non-finite numerical values and `.isin()` to
check for unexpected behavior categories.

Finally, I calculated the minimum and maximum
recorded playtime to understand the range of values.

== Purchase-Play Relationship Validation

I created the `get_purchase_play_relationships()`
function to examine how purchase and play records
are connected at the user-game level.

I used Python sets to represent unique user-game
combinations for each behavior type.

Using set intersection and difference operations,
I identified three categories:

* User-game pairs containing both purchase and play records.
* User-game pairs containing only purchase records.
* User-game pairs containing only play records.

The resoults of this are:

Among these pairs, 70,477 (54.72%) have both purchase

purchase records.

No additional cleaning is required based on
the purchase-play relationship validation.

I also checked whether the column contained

== Data Quality Assessment Summary

After completing the data quality assessment, I identified
several issues that should be addressed before performing
feature engineering and clustering.

The analysis confirmed that the dataset contains no missing
values, invalid behavior categories, negative playtime values,
or zero playtime values.

However, three issues require preprocessing:

The analysis identified 707 fully duplicated records,
representing approximately 0.35% of the dataset.
I decided to remove these redundant records because
they do not provide additional information about game
ownership and could lead to incorrect calculations
if records were counted multiple times.
The first occurrence of each duplicated record will
be retained using `drop_duplicates()`.

The analysis identified 24 play records associated
with 12 repeated user-game combinations.
These records contain different playtime values
for the same user and game.
Since the dataset does not clearly document whether
these values represent independent gaming sessions
or overlapping cumulative measurements, I decided
to retain the maximum recorded playtime for each
user-game combination.
The `groupby()` and `idxmax()` methods will be used
to identify and retain the records with the highest
playtime values.

The `extra` column contains only zero values across
all 200,000 records.

Since this column has no variation and provides
no useful information for the clustering task,
I decided to remove it from the cleaned dataset.
The `drop()` method will be used to remove this column.
